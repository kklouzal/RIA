## Confirmed defects and completed corrections

1. **Credential startup stall and boundary handling (medium availability).** The previous `fopen`/`fread` bearer loader could block indefinitely opening an unconnected FIFO. The exact prior reader block timed out in a bounded FIFO fixture (`audit-bearer-fifo-before.json`). `ria_api_bearer_read` now opens one nonblocking, no-follow descriptor, requires a bounded regular file, checks complete reading and stable descriptor metadata, closes its resource, clears output on failure and exposes no secret bytes in errors. Tokens retain the specified 1–4096 printable ASCII byte contract and optional LF/CRLF, including terminators at the maximum token size. This is a provisioned credential/configuration boundary, not an HTTP exploit claim.
2. **JSON-to-C string truncation (medium configuration integrity).** Actual `ria_server_policy` accepted embedded NUL suffixes in the API bind address and bearer path (`audit-api-policy-nul-before.json`). It now rejects incomplete C representations and empty addresses before address parsing or opening a credential.
3. **Startup cancellation was unobserved (medium availability).** The frontend's first SIGTERM/SIGINT only set its stop flag while RIA engine construction continued through TensorStore population/authentication, configuration, binding and graph construction. An explicit optional callback/context now travels through `ds4_engine_options` and the DS4 bridge to the engine. Construction polls it between phases, at existing TensorStore copy/hash progress boundaries and immediately before publishing the engine. Successful construction clears the borrowed callback/context; cancellation preserves `RIA_CANCELLED` through cleanup and returns no engine. The callback must promptly return without reentry/destruction, and its context remains valid until open returns. Default donor callers remain unchanged.
4. **Expired channel poll snapshot (medium availability).** Actual `event_loop` submitted a closed channel descriptor to `poll` after deadline invalidation (`audit-poll-snapshot-before.log`). A subsequent accept could reuse that descriptor and receive stale events. Frame/reply/started-write deadline invalidation now discards the captured snapshot and restarts before polling or accepting. Invalidation clears the triggering receive/output state, so the next iteration constructs a fresh snapshot and progresses. Three actual-loop regressions verify that no retired descriptor reaches poll and that owned reply buffers/channels are released. The poll observer injects one terminal error only after inspecting the submitted snapshot; all existing TLS/socket lifecycle cases continue to use the real OS poll.
5. **Cancellation readiness and shared signal state (medium correctness).** The exact production health function returned ready after first SIGTERM (`audit-health-signal-before.log`). Health now samples cancellation along with readiness/stopping, and readiness publication uses the frontend mutex. Every shared process signal word access uses GCC/Clang lock-free atomics, verified at compile time under existing C99 flags. Relaxed ordering communicates cancellation or descriptor-close ownership and publishes no other state. RIA signal mode is selected before engine/worker creation and remains immutable during runtime, preventing a mode-dependent handler from straddling listener publication. Atomic exchange gives donor handler/main listener close one owner; RIA retains main-thread close ownership. The actual fixture verifies cross-thread signal/health behavior, a readiness publisher racing cancellation, donor/RIA close policy and second-signal exit 130.

6. **Missing printf wrapper contracts (low build/verification).** The newly integrated fifth canonical TSan fixture exposed strict Clang `-Wformat=2` errors in inherited `buf_printf`, `server_log` and `trace_event`: their format forwarding was unannotated. That failed canonical command ran no TSan fixture. Correct GCC/Clang `printf` attributes now declare format/first-argument indexes `(2,3)`, `(2,3)` and `(3,4)`, preserving all callers and canonical flags without suppressing diagnostics. Full-source strict GCC/Clang builds found no actual format mismatch. Independent negative compiler fixtures reject an intentionally wrong argument at each wrapper, verifying all three contracts. The exact API-policy TSan build and execution subsequently passed privately; refreshed API ASan/UBSan/leak checking also passed.

7. **Grouped-worker fixture read another worker's unpublished state (medium verification, fixture only).** The refreshed canonical ASan run aborted in `test_server_prefill.c` because worker1's recording shim compared its rows with `workers[0].batch_rows` before worker0 necessarily initialized. Production uses each worker's own initialized capacity and executor; no production correction was needed. Fixture TLS now borrows the actual worker argument/context until return and verifies its own capacity/CPU owner. The two-worker affinity shim explicitly holds worker0 on the mutex/condition-protected `entered` flag until worker1 records its first evaluation; that first call checks worker index1. Both capacities are inspected only after joining both workers. The old cross-worker predicate aborts deterministically under that schedule (`audit-prefill-schedule-before.log`), while the corrected fixture passes 20 bounded ASan/UBSan/leak runs, 20 TSan runs and an NDEBUG build/run (`audit-prefill-worker-sanitize.log`, `audit-prefill-worker-thread.log`, `audit-prefill-worker-ndebug.log`). All required fixture checks/operations still execute with NDEBUG. The independent graph reviewer found no remaining TLS, startup-order, mutex/condition or lifetime defect. The failed canonical gate/log is retained; final canonical verification must use the corrected frozen fixture.

Current correction locations: `ria/engine.c` (`ria_api_bearer_read`, `ria_engine_open`), `ds4.h`/`ds4.c` (callback contract/bridge), `ds4_server.c` (process signal words, `ria_server_policy`, `ria_client_health`, startup/readiness publication), and `ria/server.c:event_loop` (expired snapshot restart).
