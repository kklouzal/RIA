## Numerical contract that must become executable

- **NVFP4:** Freeze per-module routed descriptors, group-16 E4M3 scales, global/calibrated factors, activation quantization, zero/saturation/rounding, intermediate casts, and the selected publisher-runtime scale reduction. A layer-wide calibrated maximum is prepared over the full original declared expert population, preserving gate/up distinctions. It is never recomputed over a cache, NUMA shard, selected slots, or prompt microbatch. Dynamic block quantization still acts on the actual runtime values.
- **Publisher reconciliation:** The project preserves source clamp and routing coefficient placement before down projection. Trace the pinned publisher backend through gate/up and down quantizers and casts. If its coefficient/quantizer ordering differs, record a distinct realization and explicitly decide the project's contract; matching weight values alone does not resolve this. Construct a strict W4A4 oracle that independently expresses the committed contract, including calibrated reductions. Do not let production and oracle share the same fused defect.
- **Source revision reconciliation:** The NVIDIA card identifies a source revision distinct from the native-source metadata observed in the handoff. Compare the actual pinned configurations/tensor identities and explain relevant changes; a model name does not establish equal source revisions or values.
- **FP8:** Preserve the declared E4M3FN values, 32×32 weight-scale blocks, 32-element activation groups, and UE8M0/power-of-two scale behavior. A hardware one-dimensional K-scale layout may expand/repack a shared source scale only if arithmetic and boundaries are preserved. Test unequal adjacent blocks and channel/row tiles to expose accidental per-row requantization.
- **BF16:** Widen actual source values reproducibly offline. Document that this does not recover missing master weights. Declare precisely which linear weights widen and which FP32/state/integer representations remain unchanged. BF16 is distinct from FP16; default TF32/fast math cannot silently alter sensitive operations.
- **Expert and router graph:** The gate has an upper-only clamp; up has a two-sided clamp. Preserve SiLU, multiplication, coefficient position, down-input quantization, casts, and shared addition. Routing bias affects selection rather than contribution weight. Single-rank routed contributions accumulate by increasing expert ID in FP32, followed by the shared result and declared cast; slots retain identity but do not override numerical order.
- **mHC versus Engram:** mHC mixing normalizes the flattened hc×width vector; Engram matching normalizes each stream over width. Include negative fixtures that deliberately use the wrong axis. The expert input width is 5,120 in the reviewed target, rather than the full four-stream residual width.
- **Tolerance and drift:** Freeze per-operator absolute/relative criteria and model-level teacher-forced loss/drift criteria before comparing optimized paths. Exact identity/transport/selection fixtures use exact checks. Numerical CPU/CUDA output is not promised bit-identical. Include near-tied routing, saturation, zero scales, extreme values, and nonfinite rejection; later routing can diverge from small arithmetic differences and requires measured evaluation.

Quantizer, profile, schedule, packed-state, and physical bank identities must remain separate where semantics differ. Wire FP32 transports declared values and metadata; it does not remove A4/A8 rounding inside the operator.

## Exact state and continuation gates

Generate an ownership table that names every KV/index source alias, SWA window, compressor accumulator/partial group, encoder/decoder boundary object, Engram history, mHC dependency, and image-related object. Specify production, read ranges, mutation, last consumer, host/device validity, and growth/peak functions. Account for broader indexing scans as well as final sparse-KV gathers.

One logical shared cache has one actual allocation per copy, with aliases for readers. All pages carry token positions and generations. Validity publishes only after an operation/copy completes, and buffers remain leased until all kernels/DMA readers complete. Failed or canceled transfers do not publish valid copies. Dirty state cannot lose its last current copy; immutable pages can evict without writeback only when current backing exists. Move already quantized bytes rather than repeated dequantize/requantize.

The chunk and continuation matrix must cross SWA size 128, candidate blocks of 8, compression-group boundaries, source-layer transitions, empty/all-masked attention blocks, image boundaries, and nonzero-position prompt rows. The minimal reference's decode-shaped window helper and initial-only image assertion require deliberate extensions with parity tests; removing assertions is insufficient. Teacher-forced evaluation needs all requested positions and shifted labels, with consistent image/padding/nonprediction masks.

For every turn, compare newly rendered native token IDs, complete incorporated prefix, image/content identities, logical positions, and encoding/profile/schedule identities. Reasoning-history dropping or tool-schema changes can invalidate an earlier prefix. Test exact append, earlier divergence, pending last sampled token, reset, and repeated turns. Preserve sufficient decoder history/state for exactness; a replay length cannot be inferred solely from window size. An optimized encoder-only prefill remains blocked until its full decoder SWA and continued-input state compare against the retained full-reference schedule.

## Capacity lower bounds and measurement decisions

For planning only, the reviewed dimensions yield `40 × 384 × 3 × 5120 × 2304 = 543,581,798,400` routed weight elements. These estimates exclude all padding, additional scale/global metadata, Engram, non-routed weights, replicas, runtime buffers, and startup duplicates. Actual pinned tensor inventory overrides the model.

| Routed representation | Values only | Values plus indicated group scales |
|---|---:|---:|
| FP4 / NVFP4 | 253.125 GiB | Approximately 284.766 GiB with one E4M3 byte per 16 weights; other metadata excluded |
| Required FP8 | 506.250 GiB | Approximately 506.744 GiB if the declared 32×32 weight blocks use one-byte scales; actual descriptor controls |
| BF16 | 1,012.500 GiB | Scale/storage overhead for other retained tensor classes remains additional |

A nominal decimal 512 GB equals about 476.837 GiB. Even FP8 routed values alone exceed that capacity, and the BF16 profile needs a substantially larger admitted server. A server described as 512 GiB also leaves too little capacity for FP8 plus the other required classes. The current NVIDIA card reports approximately 492 GiB for its full NVFP4 export; any target-only reduction must be inventoried and hashed, and cannot exclude active tensors merely to fit. Do not convert these lower bounds into an invented hardware minimum; compute profile-specific admission from actual usable memory and all active populations.

Record ordered objectives and hard budgets per admitted REGION from the parent-reviewed performance/admission contract and actual deployment inputs: cold startup, TTFT/prefill, decode latency distribution, append/reset costs, host/device peaks, transfer traffic, and resource cost. Evidence must control cache state, run order/warmup, background load, concurrency, versions, and uncertainty.

Decisions to measure once semantics pass:

1. SM120 implementation per operation/phase, especially sparse attention layouts, indexing, compressor production, and W4A4/W8A8 GEMMs. Compare valid compiled library/AOT donor kernels with owned native implementations where supported. Include actual launch resources and code generation.
2. Retained full-reference versus demonstrated exact CED schedules; all decoder initialization/replay work counts in TTFT and memory.
3. Device-resident versus host-backed attention/head/shared/vision tensors; tile sizes, gather/staging costs, running-softmax state, and required scale reductions count in the integrated result.
4. VRAM versus host expert cache, and host-hit CUDA staging versus remote evaluation; measure separately for prefill and decode. Cache bytes cannot crowd out admitted private state.
5. Page size and sparse read/index scan placement; compare bounded pinned staging with legal bounded registration or mapped one-touch retrieval. Record H2D/D2H separately.
6. Prompt row/expert grouping, slot sizes, and double buffering; include partition-invariant quantization and prefill's full expert union without whole-layer allocation.
7. Legal branch overlap and known-history Engram prefetch; bound queues and avoid duplicated selected-expert execution. Speculative layer advancement and approximate replay are outside the baseline candidate set.
8. CUDA graphs only when stable slot lifetimes and actual end-to-end savings justify their memory/state cost.
