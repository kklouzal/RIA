## End-to-end invariants to carry into code and tests

1. **Trust before expensive work.** Complete mTLS authentication and explicit peer/model authorization before installing handles or accepting compute. Verify trusted logical/profile/operator identities, map approved physical layouts, and atomically consume a bulk capability for the same authorized certificate identity. Bind cannot obtain its trust anchor from the service being authenticated. Runtime remote input is data, never a path, pointer, graph, kernel or downloaded executable.
2. **Validate before allocation/execution.** Read the fixed header into bounded parser storage; reject impossible kind/flag/status/session/epoch/ID/length combinations. Apply type-specific bounds, then validate small descriptors, checked exact length equations, bound dimensions, CSR monotonicity, unique row/slot/expert identities and quantizer schema before granting large buffers/workspace. A preallocated bounded receive pool is valid; allocating an attacker-declared frame and validating afterward is not. Require complete payload consumption.
3. **Admission guarantees progress.** Each accepted request owns all mandatory capacity needed to finish its bounded subgroup and send a result/error. Shared pools have explicit protected demand/drain capacity. Optional cache fills/prefetch cannot hold a resource needed to free an execution slot or send a reply. CPU/network progress remains available while compute pools are saturated.
4. **Immutable cache validity is atomic.** Keys include logical/profile identity, physical realization, scale dependencies and calibration/operator contract. A multi-projection expert entry is unavailable until all required weights/scales have verified and completed upload. Preserve leases through compute and DMA. A failed/cancelled fill never publishes a partial entry. Table rows include scale bytes and deterministic transmitted padding. Duplicate table rows retain association maps.
5. **Exactly one application, conditional transport liveness.** Match the full connection/session/epoch/request identity and immutable outstanding descriptor before consuming a result. Out-of-order completion is allowed. Reduce the complete expected local/remote set once in reference order. No missing/failed contribution enters the layer. After abandonment, even a valid successful reply is discarded for application; its terminal delivery still completes its protocol reservation once. Fatal binding loss does not synthesize terminal success.
6. **Cancellation preserves lifetime.** Mark the client generation unusable before requesting Cancel. Retain target resources and association while draining. Cancel acknowledgement owns only its own lightweight reservation. The target's terminalization is single-owner; retain 16 completed inference/row IDs in completion order plus independent active records. CPU worker joins and CUDA event/copy/TLS completion govern reclamation. An unquiescent executor exits through the tested bounded process-failure path.
7. **Mutable state and user output commit coherently.** Publish contribution/state validity only after successful work. Model state may be updated during a step but becomes unusable on any required failure; token output waits for the complete successful step. Preserve token-history, incorporated-position and sampling distinctions. Restart/recovery uses fresh binding and exact history reconstruction; no old DMA/result can write or authorize a new private generation.
8. **Modes remain explicit.** CPU-only binaries run without CUDA runtime/driver/package initialization. CUDA serving never routes misses to CPU expert mathematics. The client always uses CUDA for neural work. Allowed cryptography/parsing/tokenization/gathering/copies are measured host work. Health is bounded readiness/counter observation, not an expensive scan or proof that a failed worker was safely recovered.

## Arithmetic and capacity consequences

The document's length equations were independently evaluated with `R=64`, `E=6R`, input/output width 5,120 and zero external quantizer context:

| Case | Request payload | Response payload | Combined payload reservation |
|---|---:|---:|---:|
| One row, six remote experts | 20,584 B | 122,912 B | 143,496 B (~140.13 KiB) |
| 64 rows, 384 remote entries | 1,314,604 B | 7,864,352 B | 9,178,956 B (~8.754 MiB) |
| Two such 64-row requests | 2,629,208 B | 15,728,704 B | 18,357,912 B (~17.507 MiB) |

Each frame fits the 16 MiB ceiling. Two admitted request/result pairs already exceed that frame ceiling as an aggregate, before intermediate results, workspace, TLS/socket buffers, Engram, bulk, cancellation and pool alignment. Frame allowance is therefore neither total memory allowance nor proof that two requests fit. Every selected-expert subgroup may stream weights sequentially, but it still retains the complete reply's contributions unless a separately validated representation proves another bound. Lower row/frame/byte limits must select legal smaller microbatches without changing a quantizer's reduction domain.

Server capacity reports must count source/active layouts, physical NUMA copies, page-cache/copy peaks, coarse arena mapping/alignment/fragmentation, per-node scratch and transport reserve. CUDA admission additionally includes executable tiles/groups, input/output slots, quantizer intermediates, cache leases and pinned staging. Do not count memory registration as a second allocation unless it creates separate backing. Do not claim NUMA replicas from several mappings of the same file or count unused model components as required full-server replicas.

## Bounded primary-source verification

The following documentation was checked on 2026-10-03. These are contract confirmations and implementation constraints; they are not target performance evidence or immutable source pins.

- **TLS early data and mTLS completion:** RFC 8446 explains that early data lacks cross-connection replay protection and permits some server application data before receiving client Finished. Therefore “handshake progress” is insufficient proof that the client has authenticated. Model admission must wait for the library's completed, verified mTLS state; application authorization remains separate. Disabling early data follows the document's existing requirement. [RFC 8446, Sections 2.3 and 4](https://www.rfc-editor.org/rfc/rfc8446.html).
- **TLS IO progress:** OpenSSL documents that a read on a nonblocking socket can require write readiness, and successful reads may return only part of the application's frame. The reactor must track the library's requested readiness direction, buffered decrypted bytes and the application frame cursor; socket readability alone is insufficient. [OpenSSL SSL_read](https://docs.openssl.org/3.6/man3/SSL_read/).
- **GPU drainage and priority:** CUDA stream destruction can return before stream work finishes, so destroying a stream is not a buffer-reuse fence. CUDA stream priorities affect compute scheduling and do not prioritize H2D/D2H copies. Demand priority therefore requires host admission/staging control and completion fences rather than a priority-stream label alone. [CUDA Runtime Stream Management](https://docs.nvidia.com/cuda/cuda-runtime-api/cuda_runtime_api/group__CUDART__STREAM.html).
- **Fatal GPU errors:** CUDA documents illegal-address and kernel-timeout outcomes as leaving the process inconsistent and requiring process termination/relaunch. This supports the architecture's process-failure policy and forbids same-process reuse of suspect buffers as recovery. Relaunch still needs a valid device/operator condition and must not be claimed safe when teardown is stuck. [CUDA Runtime error contracts](https://docs.nvidia.com/cuda/cuda-runtime-api/cuda_runtime_api/group__CUDART__TYPES.html).
- **NUMA physical replicas:** Linux documents that already-faulted pages retain placement unless explicitly migrated, and ordinary file page-cache pages are shared and do not follow a mapping's VMA policy in the way an anonymous replica does. Local affinity plus repeated file mapping is insufficient evidence of distinct local copies. Verify actual pages and independent physical memory where replication is claimed. [Linux NUMA Memory Policy](https://www.kernel.org/doc/html/latest/admin-guide/mm/numa_memory_policy.html).
